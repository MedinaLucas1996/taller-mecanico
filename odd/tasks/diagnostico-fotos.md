# Feature: diagnostico-fotos (mechanic diagnosis before the budget and work photos)

Objective: let the mechanic write a diagnosis while the order is RECEPCIONADA (optional, with a warning when budgeting without it) and upload work photos during the job, printed in their own sheet. Branch `feature/TM-0019` from `main` at 87d67f6. Delivery strategy: single-pr. Test runner: none; checks are a clean `dotnet build` to a scratch OutDir and the off-screen render harness (read paths only; print pages through a `PreviewPrintController`).

Style (mandatory): the professor's event-driven VB.NET: designer-built controls (`.Designer.vb`, `Friend WithEvents`, handlers with `Handles`; no `AddHandler`, no controls created in code), SQL in the form with `Using cn As New MySqlConnection(CADENA)` / `Using cmd` and `AddWithValue`, validation ending in `Exit Sub`, multi-step saves in `BeginTransaction` with `Commit` outside the inner Try, short lowercase Spanish comments without accents, `Sesion.ROL_*` for roles, `MessageBox.Show` for errors, `LeerIcono` for icons, reports as a designer `PrintDocument` + `PrintPreviewDialog` drawn with the `Module Impresion` helpers. No DAO, no new packages. UI texts in neutral Spanish. Keep CRLF in the working copy.

## Specs

- S1 Schema.
  - New nullable `TEXT` column `orden_trabajo.diagnostico`.
  - New table `ot_foto_trabajo` (id, `id_orden_trabajo` FK, `imagen` LONGBLOB, `descripcion` short VARCHAR, `id_usuario` FK, `fecha_hora` DATETIME default now), unlimited photos per order. `ot_foto` (five fixed angles, unique per order and angle, feeds the reception act) is NOT reused.
  - New idempotent migration `database/09_diagnostico_fotos.sql` (like `07_recepcion_fotos.sql`); `database/01_ddl_estructura.sql` creates both; the specification goes from 13 to 14 tables. `taller-mecanico.dbml` is not kept current (it still describes the 12 original tables and already omits `ot_foto`), so it stays as is.
- S2 `FrmMisOrdenes`: new group "Para diagnosticar" listing the mechanic's orders in RECEPCIONADA. Assumption: it is a fourth card after "Para empezar" (En curso · Para empezar · Para diagnosticar · Terminadas); the subtitle also counts it; the summary button reads "Cargar diagnóstico" for those orders.
- S3 `FrmOrdenGestion` mechanic mode, order RECEPCIONADA: instead of "Esperando el presupuesto", a text box for the diagnosis and a "Guardar diagnóstico" button. The state does not change. The save runs in a transaction that locks the order, re-checks that it is still RECEPCIONADA and still assigned to the mechanic (like the other mechanic actions), updates `diagnostico` and inserts an `ot_historial_estado` row "Diagnóstico cargado" with the current `id_estado_ot` and `Sesion.IdUsuario`. Assumption: closing with unsaved diagnosis text asks before closing, like the unsaved work progress.
- S4 Administrador/operador with the order RECEPCIONADA: the diagnosis shown read-only above the budget lines. When budgeting with an empty diagnosis, a warning (Yes/No to continue), never a hard block. Assumption: the read-only diagnosis also shows while PRESUPUESTADA when it has text, since the client approves against it.
- S5 Printed: the diagnosis appears in the budget and work order sheets (`FrmOrdenGestion` print routines) and per order in the printed vehicle history (`FrmHistorial`); only when it has text. The reception act does not carry it.
- S6 Work photos in `FrmOrdenGestion`: upload by the assigned mechanic, administrador and operador while the order is RECEPCIONADA or EN_PROCESO; remove allowed until FINALIZADA (interpreted as any state before it: RECEPCIONADA, PRESUPUESTADA, APROBADA, EN_PROCESO), by the same roles. Each save re-checks state and, for the mechanic, ownership inside a locking transaction. Reuse `Fotos.LeerFotoComoJpeg` (1280 px JPEG) and `FrmFoto` (view only) for the enlarged view; thumbnails in `FrmOrdenGestion` (with an optional short description typed before uploading) and in `FrmMisOrdenes`.
- S7 New item "Fotos del trabajo" in the Imprimir menu of `FrmOrdenGestion`: a separate paginated sheet with the photos and their descriptions, no amounts, every role.
- S8 `README.md` and `doc/Docu.md` updated; README status drops "Pendiente en el flujo de la orden de trabajo: diagnóstico escrito por el mecánico antes del presupuesto y fotos cargadas por el mecánico".
